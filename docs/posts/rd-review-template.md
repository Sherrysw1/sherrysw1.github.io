# 研发复盘模板

研发复盘要避免只写结论，应该保留足够上下文，让以后能复用。

## 模板

### 现象

用户或系统看到了什么异常？

### 影响

影响范围、严重程度、持续时间是什么？

### 根因

直接原因和深层原因分别是什么？

### 修复

采取了哪些修复动作，如何验证？

### 后续

哪些监控、测试、文档或流程需要补齐？

> 好的复盘应该把问题变成可消费的知识，而不是只把事故关掉。
